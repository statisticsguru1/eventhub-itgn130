# EventHub submission checklist

All items are outstanding until evidence is recorded. This checklist records
assignment obligations, not completed deliverables. Do not include real sensitive
participant information in sample data. Required group attribution is separate
from fictional application sample records.

## Source, samples, and portability

- [ ] Include complete Python source files (.py), with meaningful functions,
  readable names, PEP 8 formatting, and brief explanatory comments (P73–75, P83).
- [ ] Include original nonsensitive sample JSON events, registrations, and waiting
  lists in sample eventhub.json (P69, P76, P83). Milestone 2.3 approves one
  authoritative snapshot; the starter file layout (P94) is suggested, not exclusive.
- [ ] Include setup/run instructions with Python 3.10+ requirement, required files,
  data location, first run, controlled storage errors, and manual data-preservation guidance (P77, P83).
- [ ] Test execution from the submitted files on another computer/clean directory.
  Starter suggests README.txt (P95); ensure actual supplied instructions are easy
  to open, whether README.md or a submission text copy.
- [ ] Exclude virtual environments, caches, personal runtime data, credentials,
  temporary files, and damaged-data investigation copies from the final ZIP.

## Group PDF report — 5–10 pages (P84)

- [ ] Overview and requirements.
- [ ] Design and program structure.
- [ ] Test cases with screenshots and actual results.
- [ ] Challenges, troubleshooting, and run instructions.
- [ ] Each student's identifiable contribution and technical explanation.
- [ ] Verify PDF readability and page count.

## Tests and demonstration evidence (P71, P88; rubric)

- [ ] Normal registration.
- [ ] Full capacity with FIFO waiting list.
- [ ] Registration cancellation with automatic promotion.
- [ ] Demonstrate persistence by saving, restarting, and reloading.
- [ ] Record screenshot-supported tests, expected/actual results, edge cases,
  validation errors, and troubleshooting; distinguish planned from executed tests.
- [ ] Rehearse a working live demonstration including capacity and promotion.

## PowerPoint and live presentation (P85–88)

- [ ] Prepare .pptx with 10–15 slides: problem, design, features, screenshots,
  tests, lessons learned.
- [ ] Prepare a 10–15 minute group presentation followed by instructor questions.
- [ ] Every student speaks, explains their identified contribution, and answers
  questions about their work and the complete application.

## Group responsibilities (P48, P54–55, P79–81)

- [ ] Maximum four students; record each member's name, student ID, and specific
  contributions in the required submission attribution.
- [ ] Define roles; maintain effective communication and collaboration.
- [ ] All students participate in development and understand the whole application.
- [ ] Each student has an identifiable documentation contribution.
- [ ] Review individual documentation/presentation evidence: grading assigns 5
  shared code marks, 5 individual documentation marks, 5 presentation marks.

## Packaging and administration (P49, P97–99)

- [ ] Include code, sample data, instructions, PDF report, and .pptx together.
- [ ] Name ZIP EventHub_<GroupID>.zip using group student IDs, for example
  EventHub_12345_67890.zip. All files must be clearly labelled/readable.
- [ ] Verify ZIP contents and perform a run from a fresh extraction.
- [ ] Submit the complete ZIP through Moodle; attend the compulsory presentation.
- [ ] Verify deadline and presentation date/time on Moodle; none is invented here.
- [ ] Verify academic year with instructor/Moodle: filename says Fall 2026–27;
  internal document heading P4 says Academic Year 2025–26.
